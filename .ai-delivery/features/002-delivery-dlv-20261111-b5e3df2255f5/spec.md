# 最小状态页产品规格

## 产品目标与边界

本规格将已批准的最小流程验证意图转化为可观察、可验收的产品契约。产品仅向团队成员提供标题为“最小流程验证”的首页、一个状态区域，以及状态获取失败后的人工重试能力，用于验证页面正常加载、状态获取成功、失败提示和人工重试四类场景（INT-001、INT-003、INT-005～INT-008、INT-013、INT-015）。

产品必须保持单页、单一固定状态的最小范围。登录、权限控制、数据库、外部系统集成、后台管理、多页面导航、复杂视觉设计及其他业务功能均不属于本次交付（INT-002、INT-004、INT-009～INT-011）。状态获取遵守 INT-012 已批准的单一只读来源约束；本规格仅定义用户可见结果，不增加实现设计。

## 参与者与权限

- **团队成员（主要参与者）**：能够访问交付页面的流程执行者或观察者，可以打开首页、查看状态结果，并在失败后发起重试（INT-003、INT-007、INT-014）。
- **产品负责人（业务提出方）**：依据本规格确认四类约定场景及范围边界是否满足，但不具有本次范围内的专属页面操作（INT-003、INT-008）。
- 页面不提供登录、身份识别、角色管理或差异化权限。任何已获得页面访问条件的团队成员拥有相同的只读查看与重试能力（INT-009、INT-014）。

## 用户故事

### US-001 查看最小状态页（P1）

作为能够访问页面的团队成员，我希望打开标题明确且范围单一的状态页，以便确认页面能够正常加载并成为完整交付流程的用户可见验证对象（INT-001、INT-003、INT-005、INT-008、INT-014）。

### US-002 查看成功状态（P1）

作为团队成员，我希望状态获取成功后看到固定状态“ok”，以便明确确认成功场景符合约定（INT-001、INT-006、INT-008、INT-012）。

### US-003 从状态获取失败中人工恢复（P1）

作为团队成员，我希望状态获取失败时看到明确提示并能够人工重试，以便验证失败场景并在条件恢复后重新获得状态（INT-001、INT-007、INT-008、INT-015）。

## 功能需求

- **FR-001**：产品必须提供标题恰为“最小流程验证”的首页，并且页面只包含一个承载状态过程与结果的状态区域（INT-005、INT-010）。
- **FR-002**：团队成员打开首页后，产品必须发起一次状态获取，并在结果确定前显示非成功、非失败的处理中状态（INT-001、INT-006、INT-008）。
- **FR-003**：状态获取成功时，唯一状态区域必须展示固定、区分大小写的文本“ok”，不得展示其他业务状态（INT-006、INT-012）。
- **FR-004**：状态获取失败时，唯一状态区域必须展示用户能够识别为获取失败的明确提示，不得将失败表现为“ok”，并必须提供可操作的人工重试入口（INT-007、INT-008）。
- **FR-005**：用户发起人工重试后，产品必须执行一次新的状态获取；重试期间回到处理中状态，并以本次结果替换先前失败结果（INT-007、INT-008、INT-015）。
- **FR-006**：重试成功时必须展示“ok”；再次失败时必须继续展示明确失败提示并保留人工重试入口，允许用户再次尝试（INT-007、INT-008）。
- **FR-007**：产品不得提供登录、权限管理、数据维护、后台管理、页面导航或状态页以外的业务操作（INT-002、INT-009～INT-011）。

## 产品质量要求

- **NFR-001**：首页页面主体必须在用户打开页面后 2 秒内可用；首次和每次重试状态获取必须分别在触发后 3 秒内进入成功或失败状态，正常及重试路径采用同一验收边界（INT-001、INT-008、INT-013）。
- **NFR-002**：本次交付不承诺长期可用率；对每个精确 Candidate 必须各执行成功、失败和恢复场景一次且全部通过，任何一次未按 FR-003～FR-006 的契约表现即判定该 Candidate 可靠性验收失败（INT-001、INT-007、INT-008、INT-013）。
- **NFR-003**：页面不得收集、要求、展示或记录用户凭据、个人信息、secret 或客户内容；状态查看和重试均不产生业务数据写入（INT-004、INT-009、INT-012、INT-013）。
- **NFR-004**：页面必须满足 WCAG 2.2 AA；所有操作均可通过键盘完成，焦点可见，处理、成功和失败结果可被辅助技术感知，且状态含义不能仅依靠颜色区分（INT-003、INT-005、INT-007、INT-013）。
- **NFR-005**：正常加载、成功、失败和重试四类用户可见能力必须分别具有可独立执行、结果确定的验收场景（INT-008、INT-013、INT-015）。
- **NFR-006**：页面必须保持最小视觉与交互复杂度，不得因装饰或附加内容引入新的业务功能、依赖或验收场景（INT-002、INT-010、INT-011）。

## 领域术语

- **最小状态页**：仅含规定标题和单一状态区域、用于完整交付流程验证的首页（INT-001、INT-005）。
- **状态获取**：从已批准的单一只读状态来源取得固定结果的业务动作（INT-006、INT-012）。
- **状态区域**：在同一位置呈现处理中、成功或失败状态以及适用操作的唯一页面区域（INT-005、INT-007）。
- **人工重试**：用户在失败后明确发起一次新的状态获取，而非产品自行重复尝试（INT-007）。
- **明确失败提示**：用户无需推断即可识别状态未能取得的可见信息；具体简短措辞不改变业务含义（INT-007）。

## 前置条件与触发条件

- 用户已获得页面访问条件；提供访问条件本身属于交付依赖，不在页面功能范围内（INT-014）。
- 打开首页触发页面加载和首次状态获取（INT-001、INT-005、INT-006）。
- 仅当当前状态为获取失败时，用户操作人工重试入口才触发新的状态获取（INT-007）。
- 成功状态不触发自动刷新，失败状态不触发自动重试（INT-002、INT-007、INT-010、INT-011）。

## 行为模型

### US-001 页面正常加载

- **正常路径**：用户打开首页；页面显示规定标题和唯一状态区域；状态区域先显示处理中状态，再进入成功或失败状态（FR-001、FR-002；AC-001、AC-002）。
- **边界路径**：状态结果尚未确定时，页面不得提前显示“ok”或失败结论（FR-002；AC-002）。
- **错误路径**：状态获取失败不应导致标题或状态区域消失，而应进入 US-003 的失败路径（FR-004；AC-004）。

### US-002 状态获取成功

- **正常路径**：首次状态获取成功后，状态区域显示且仅显示业务状态“ok”（FR-003；AC-003）。
- **替代路径**：失败后的人工重试成功时，先前失败提示被“ok”替换（FR-005、FR-006；AC-006）。
- **边界路径**：除“ok”外不定义或展示第二种成功业务状态（FR-003、FR-007；AC-003）。

### US-003 失败提示与人工重试

- **错误路径**：状态获取失败时，状态区域显示明确失败提示和人工重试入口，不伪造成功状态（FR-004；AC-004）。
- **恢复路径**：用户发起重试后进入处理中状态；成功则显示“ok”，失败则重新显示失败提示和重试入口（FR-005、FR-006；AC-005～AC-007）。
- **边界路径**：连续失败时，每次用户重试仅代表一次新尝试；页面保持一个状态区域和一个适用的重试入口，不叠加历史结果或附加功能（FR-001、FR-006、FR-007；AC-007）。

## 业务状态、业务数据规则与不变量

业务状态依次受以下转换约束：

- **待加载 → 处理中**：用户打开首页。
- **处理中 → 成功**：本次状态获取成功。
- **处理中 → 失败**：本次状态获取失败。
- **失败 → 处理中**：用户发起人工重试。
- **成功**：本次用户旅程终态；产品不自动刷新。

业务数据规则与不变量：

1. 成功业务值恒为区分大小写的“ok”，不存在其他有效成功值（INT-006、INT-012）。
2. 任一时刻只有一个当前状态，不同时展示相互冲突的处理中、成功和失败结论（INT-005、INT-008）。
3. 状态获取和重试均为只读行为，不改变业务数据（INT-012）。
4. 失败不会被解释为成功；只有一次成功的状态获取才能进入成功状态（INT-006、INT-007）。
5. 人工重试只能由失败状态下的用户操作触发；不提供自动重试或成功后的刷新能力（INT-002、INT-007、INT-010、INT-011）。

## 错误与恢复行为

- 任何未取得有效成功结果的状态获取均按失败处理，向用户显示明确失败提示和人工重试入口（INT-007、INT-008）。
- 失败提示不得包含凭据、secret、客户内容或不必要的内部信息（INT-004、INT-009、INT-013）。
- 重试开始后，旧失败结论不再作为当前状态；页面显示处理中状态以防止用户误认为重试尚未发生（INT-007）。
- 重试再次失败时维持相同的可恢复产品契约；本次范围不规定重试次数上限，也不增加自动重试、升级、通知或历史记录（INT-002、INT-007、INT-009～INT-011）。

## 安全、隐私与可访问性行为

- 页面无登录、权限控制和差异化角色；仅面向已具备访问条件的团队成员，不扩展公开访问承诺（INT-003、INT-009、INT-014）。
- 页面不接受状态查看和重试之外的业务输入，不收集个人信息、客户内容或凭据，不展示 secret，并只允许只读状态行为（INT-004、INT-009、INT-012、INT-013）。
- 失败信息仅表达用户可采取行动的结果，不暴露不必要的内部信息（INT-007、INT-013）。
- 标题、状态文字、失败提示和重试入口必须可被辅助技术识别；重试可通过键盘完成；焦点可见；状态含义不只依靠颜色表达（INT-003、INT-005、INT-007、INT-013）。
- 页面整体必须满足 WCAG 2.2 AA，且上述键盘、焦点、辅助技术和非纯颜色要求均须独立验证。

## 性能、可靠性与其他质量边界

- 首页页面主体须在打开后 2 秒内可用；首次及每次重试状态获取须在触发后 3 秒内进入成功或失败状态。
- 本次不承诺长期可用率；每个精确 Candidate 的可靠性验收须各执行成功、失败和恢复场景一次，三次均须按契约通过，任何一次不符合即失败。
- 在状态结果尚未返回时，处理中状态必须持续反映真实未决状态，不得以虚假成功满足时限。
- 任一质量目标不得通过增加已排除功能、系统依赖或复杂视觉设计实现（INT-002、INT-009～INT-011）。

## 成功标准

- **SC-001**：四类约定场景——页面正常加载、状态获取成功、状态获取失败提示、人工重试——均有至少一个独立场景通过，覆盖率为 4/4（INT-001、INT-008、INT-015）。
- **SC-002**：在所有成功场景中，观察到的成功业务状态均为“ok”，其他成功业务状态出现次数为 0（INT-006、INT-012）。
- **SC-003**：在所有失败场景中，明确失败提示和可操作的人工重试入口出现率均为 100%，将失败显示为“ok”的次数为 0（INT-007、INT-008）。
- **SC-004**：验收中发现的范围外业务功能、外部业务系统依赖或额外页面数量均为 0（INT-002、INT-004、INT-009～INT-011）。
- **SC-005**：同一精确 Candidate 的首页页面主体可用时间不超过 2 秒，首次及每次重试状态获取进入成功或失败的时间不超过 3 秒；成功、失败和恢复场景各执行一次且 3/3 通过；页面满足 WCAG 2.2 AA（INT-001、INT-003、INT-005、INT-007～INT-008、INT-013）。

## 验收场景

### IQA-001 首页正常加载

- **追踪：** INT-001 / INT-003 / INT-005 / INT-008 / INT-014 / US-001 / FR-001～FR-002 / NFR-005～NFR-006 / AC-001～AC-002
- **前置条件：** 团队成员具备页面访问条件，状态结果保持未决直至检查完成。
- **操作：** 打开首页并观察标题和状态区域。
- **预期结果：** 页面可访问；标题恰为“最小流程验证”；仅有一个状态区域；结果未决期间显示处理中状态，未提前显示成功或失败。
- **必需证据：** 可识别 Candidate 的页面观察记录，包含标题、单一状态区域和处理中状态。

### IQA-002 首次状态获取成功

- **追踪：** INT-001 / INT-006 / INT-008 / INT-012 / US-002 / FR-002～FR-003 / AC-003
- **前置条件：** 团队成员具备页面访问条件，已批准状态来源可返回成功结果。
- **操作：** 打开首页并等待状态获取完成。
- **预期结果：** 唯一状态区域从处理中转为成功，并显示且仅显示固定业务状态“ok”。
- **必需证据：** 可识别 Candidate 的完整状态转换及最终“ok”记录。

### IQA-003 首次状态获取失败

- **追踪：** INT-001 / INT-007～INT-008 / US-003 / FR-004 / NFR-003 / AC-004
- **前置条件：** 团队成员具备页面访问条件，可使首次状态获取产生真实失败结果。
- **操作：** 打开首页并等待失败结果。
- **预期结果：** 页面保留标题和唯一状态区域；显示明确失败提示及一个人工重试入口；不显示“ok”、secret、客户内容或不必要的内部信息。
- **必需证据：** 可识别 Candidate 的失败页面记录及对敏感内容缺失的观察结果。

### IQA-004 失败后人工重试成功

- **追踪：** INT-001 / INT-007～INT-008 / INT-015 / US-003 / FR-005～FR-006 / AC-005～AC-006
- **前置条件：** 页面处于失败状态，下一次状态获取可成功。
- **操作：** 用户操作人工重试入口并等待结果。
- **预期结果：** 页面先显示处理中状态，随后以“ok”替换旧失败结果；用户无需重新打开页面。
- **必需证据：** 可识别 Candidate 的失败、用户操作、处理中和成功结果连续记录。

### IQA-005 连续失败后再次恢复

- **追踪：** INT-002 / INT-007～INT-011 / INT-015 / US-003 / FR-005～FR-007 / AC-005～AC-008
- **前置条件：** 页面处于失败状态，第一次重试失败，第二次重试成功。
- **操作：** 连续发起两次人工重试并观察每次结果。
- **预期结果：** 第一次重试失败后仍显示单一失败提示和单一重试入口；第二次重试成功后显示“ok”；不出现自动重试、历史列表、额外页面或附加业务功能。
- **必需证据：** 可识别 Candidate 的两次独立用户操作及各状态转换连续记录。

### IQA-006 最小权限与隐私边界

- **追踪：** INT-003～INT-004 / INT-009 / INT-012～INT-014 / US-001～US-003 / FR-007 / NFR-003 / AC-009
- **前置条件：** 团队成员具备页面访问条件。
- **操作：** 完成正常、失败和重试旅程，并检查所有用户可见内容和可用操作。
- **预期结果：** 不要求登录或个人信息；不提供差异化权限、写入或范围外业务操作；不展示凭据、secret 或客户内容。
- **必需证据：** 可识别 Candidate 的完整页面内容与操作清单，以及三类旅程观察记录。

### IQA-007 键盘与可感知状态

- **追踪：** INT-003 / INT-005 / INT-007 / INT-013 / US-001～US-003 / NFR-004 / AC-010
- **前置条件：** 页面可访问，并可分别观察处理中、成功和失败状态。
- **操作：** 仅使用键盘完成失败后的重试，并使用辅助技术检查标题、状态变化、失败提示与重试入口。
- **预期结果：** 操作全程可完成且焦点可见；各状态及变化可被感知；状态含义不只依靠颜色；页面满足 WCAG 2.2 AA。
- **必需证据：** 可识别 Candidate 的键盘操作、辅助技术观察记录和 WCAG 2.2 AA 验收结果。

### IQA-008 外部质量边界

- **追踪：** INT-001 / INT-008 / INT-013 / US-001～US-003 / NFR-001～NFR-002 / AC-011～AC-012
- **前置条件：** 团队成员具备页面访问条件，并可使同一精确 Candidate 分别产生成功、失败和恢复结果。
- **操作：** 测量首页页面主体可用时间、首次及每次重试状态获取进入成功或失败的时间；对该 Candidate 各执行成功、失败和恢复场景一次。
- **预期结果：** 页面主体在 2 秒内可用，每次状态获取在 3 秒内进入成功或失败；成功、失败和恢复场景 3/3 按契约通过，任何一次不符合即判定本场景失败，且不以虚假成功或范围扩展规避失败。
- **必需证据：** 可识别 Candidate、测量起止条件、三类场景的原始结果、响应时间和逐项边界判定的验收记录。

## 验收标准

- **AC-001**：团队成员在具备访问条件时能够打开首页，并看到标题恰为“最小流程验证”和唯一状态区域（INT-001、INT-005、INT-014）。
- **AC-002**：首次状态结果确定前，状态区域显示处理中状态，且不显示成功或失败结论（INT-001、INT-008）。
- **AC-003**：首次或重试状态获取成功后，状态区域显示且仅显示固定业务状态“ok”（INT-006、INT-012）。
- **AC-004**：状态获取失败后，页面显示明确失败提示和人工重试入口，不显示“ok”（INT-007、INT-008）。
- **AC-005**：每次人工重试均由用户明确操作触发，并进入一次新的处理中状态（INT-007）。
- **AC-006**：人工重试成功后，“ok”替换先前失败结果，无需重新打开页面（INT-007、INT-008）。
- **AC-007**：人工重试再次失败后，页面继续提供明确失败提示和人工重试入口，允许后续再次尝试（INT-007、INT-015）。
- **AC-008**：页面不提供自动重试、成功后刷新、历史记录、额外页面或其他业务功能（INT-002、INT-009～INT-011）。
- **AC-009**：完整用户旅程不要求或展示凭据、个人信息、secret 或客户内容，不提供写入或差异化权限操作（INT-004、INT-009、INT-012～INT-013）。
- **AC-010**：页面满足 WCAG 2.2 AA；所有操作可用键盘完成且焦点可见，状态和失败提示可被辅助技术感知且不只依靠颜色（INT-003、INT-005、INT-007、INT-013）。
- **AC-011**：首页页面主体在打开后 2 秒内可用，首次和每次重试状态获取均在触发后 3 秒内进入成功或失败状态（INT-001、INT-008、INT-013）。
- **AC-012**：对同一精确 Candidate 各执行成功、失败和恢复场景一次且 3/3 按契约通过；任何一次不符合即判定可靠性验收失败，不要求长期可用率（INT-001、INT-007～INT-008、INT-013）。

## 测试策略

### 开发者验证

- 对 FR-001～FR-007、业务状态转换和五项不变量进行确定性验证，至少覆盖首次成功、首次失败、重试成功、连续失败后再次成功以及未决状态边界。
- 验证错误内容不含凭据、secret、客户内容或不必要内部信息，并验证页面不存在登录、写入、自动重试、额外页面和其他范围外操作。
- 验证首页页面主体在 2 秒内可用、首次及每次重试状态获取在 3 秒内进入成功或失败；对同一验证对象各执行成功、失败和恢复场景一次，并验证三次均按契约通过。
- 验证页面满足 WCAG 2.2 AA，包括键盘可操作、焦点可见、状态可被辅助技术识别且不只依赖颜色。
- 开发者验证可提供快速反馈，但不能替代针对精确 Candidate 的 Independent QA 用户可见验收证据。

### Independent QA 验收

- 针对待验收的精确 Candidate 独立执行 IQA-001～IQA-008；必须记录 Candidate 身份、前置条件、操作、真实结果和原始证据，不得以构造的替代结果声称用户可见行为通过。
- IQA-001～IQA-007 验证页面及完整用户旅程，其中 IQA-007 按 WCAG 2.2 AA 执行；IQA-008 按 2 秒页面主体可用、3 秒状态结果和三类场景 3/3 通过的边界执行。
- 每个失败场景必须观察真实的产品失败表现和人工恢复旅程；页面加载成功、静态检查、构建成功或仅检查存活不能替代功能验收。

### 总体通过与失败标准

- **通过**：IQA-001～IQA-008 对同一精确 Candidate 全部通过；AC-001～AC-012 和 SC-001～SC-005 全部满足；不存在范围外功能或依赖。
- **失败**：任一必需场景未执行、证据不可归属于同一精确 Candidate、任一 AC/SC 未满足，或发现未经批准的范围扩展，均判定总体不通过。

## 假设、依赖与范围外边界

**低影响规格假设：**

1. 首页打开后自动开始首次状态获取；这避免增加一个未经要求的初始操作，不改变已批准四类场景（INT-001、INT-006、INT-008）。
2. 处理中状态使用简短可感知提示，失败提示可采用任意简短措辞，只要满足“明确失败提示”的定义；具体文案和视觉样式不改变验收语义（INT-005、INT-007）。
3. 人工重试次数不设产品上限；每次重试保持同一行为，不增加计数、历史或升级功能（INT-002、INT-007、INT-010）。

**依赖：**

- 团队成员能够访问交付页面（INT-014）。
- 后续阶段保持本规格的最小范围，并提供同一精确 Candidate 的四类用户可见场景和质量边界验收条件（INT-013、INT-015）。
- Independent QA 能够对同一精确 Candidate 形成成功、失败和恢复结果，并取得响应时间及 WCAG 2.2 AA 验收证据（INT-001、INT-003、INT-007～INT-008、INT-013）。

**范围外边界：**

- 登录、身份与权限管理、数据库、外部业务系统集成、后台管理、多页面导航、复杂视觉设计、自动重试、状态历史、通知、状态写入、额外业务状态和其他业务功能均在范围外（INT-002、INT-004、INT-009～INT-011）。
- 不因本规格定义测试策略而增加面向最终用户的测试控制、故障控制或诊断功能。
